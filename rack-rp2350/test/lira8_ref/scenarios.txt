# LIRA-8 golden scenarios — shared protocol for the pd driver (drive_ref.py)
# and the C++ engine renderer (render_golden). Format per line:
#   <t_ms> <selector> <args...>        # event (sensor N v | param NAME V)
#   <t_ms> render <file>               # writesf start (pd side)
#   <t_ms> stop                        # writesf stop
# Lines starting with # are comments; each scenario starts at 'SCEN <name>'.
# NOTE: delay time params stay <= 105 (<=919 ms) — the RP2350 engine caps
# storage at 1.45 s, so longer pd times would diverge by design.
# FEEDBACK boundary: the RP2350 int16 delay (+-2 headroom) hard-clips the
# compander's transient overshoots when loop gain > ~1.4 (feedback > ~65).
# fb=100 (g=2.35) self-oscillates into distortion EVEN IN PD (float loop
# rides the transients) — keep golden scenarios at feedback <= 60.
# Five full trajectories (drone-all, single-pair, delay-extremes, fuzz-push,
# transients) and drone-nodelay explicitly initialize all 47 params + sensors
# off at t=0, overriding the saved parameter fixture on both sides.
# Eight partial-init probes (onetest, pairnofm, pairfm, onecyc, pitch0,
# pitch127, cleantest, onevoice) inherit unspecified saved/default state;
# all eight explicitly set delay mix to zero.
