# Rings RP2350 — port plan (fork MiniElements Rings, 5 modes, one firmware)

Source: **lylepmills/eurorack** fork (same `EURORACK-STEREO` submodule as
plaits, pinned `83f86ae`), path `rings/` — the fork's Rings is the
"MiniElements" alt firmware: stock Rings DSP + internal Elements-style
exciters + string-synth easter egg, stereo = out/aux ODD/EVEN convention.
Replaces PORTING-HIGHLIGHTS §9 prep, which was written against poetaster's
rings and is wrong for this fork in four load-bearing ways (survey
2026-11-03): rate is 32 kHz/24-block (not 48/32), there is **no** `Dsp::setSr`
(no rate setter at all), RAM is ~184 KB worst case (not 55-60), and there is
no STM32 leak inside `dsp/` (no settings/user_data stub needed).

## Key fork facts (survey)

- Two Parts, one runs per block: `Part` (modes 0-3) and `StringSynthPart`
  (mode 4 easter egg). `PerformanceMode`: 0 RINGS_STEREO, 1 RINGS_WAVEFORM,
  2 MINI_ELEMENTS_STEREO, 3 MINI_ELEMENTS_EXCITER, 4 EASTER_EGG.
- `ResonatorModel` 0-5 (modal / sympathetic / /2quantized / string /+reverb /
  fm-voice) via `Part::set_model()`; easter egg reuses the byte as FxType
  (formant/chorus/reverb/…). Polyphony 1-4 (`set_polyphony`, 8 strings,
  4 resonators, fixed members — polyphony-independent RAM).
- `Patch` = 4 floats: structure, brightness, damping, position.
  `PerformanceState` carries mode/chord_table/tonic/note/fm/chord/
  internal_exciter/strum/waveform_exciter/… — **fresh struct per block**
  (firmware contract), state lives in the Parts.
- Per-block contract (rings.cc:88-127): fill patch+performance_state →
  `part.Process(state, patch, in, out, aux, 24)` (easter egg:
  `string_synth.Process(...)`) → out=L, aux=R. Strummer/OnsetDetector
  DROPPED (we drive `strum` from MIDI note-ons; `internal_strum=false`).
- `internal_exciter=true` → MODAL gets a pulse, STRING a pluck burst, FM an
  envelope — fully standalone. MiniElements modes add bow/blow/strike
  exciters (blow/strike read the 338 KB `smp_*` sample ROMs in resources.cc —
  flash-resident, do NOT SRAM).
- Init: `part.Init(reverb_buffer)`, `string_synth.Init(reverb_buffer)` over
  ONE caller-owned `uint16_t reverb_buffer[32768]` (64 KB; reverb/chorus/
  ensemble point at it — mutually exclusive by mode).
- No BufferAllocator, no malloc/double anywhere in `dsp/`. RAM worst case
  ≈ 120 KB Part + 2.4 KB StringSynthPart + 64 KB reverb buffer.
- stmlib: 9 DSP headers, all present in poetaster's STMLIB (units.cc already
  in our lib from elements). ui/event_queue + test/wav_writer needed only by
  excluded files.
- `bryanChords` in part.cc is non-const (1.4 KB in .data) → const patch.

## Architecture decisions

| Decision | Choice | Why |
|---|---|---|
| Scope | All 5 modes + all 6 models + easter egg in one build | RAM fits (~125 KB without reverb buffer prunes) |
| Rate | I2S **32 kHz**, block = `kMaxBlockSize` (24), budget 750 µs (multiply-first) | Constants baked at compile time; no setter exists |
| Stereo | out/aux → L/R directly (ODD/EVEN convention, firmware-identical) | Fork's stereo convention |
| Excitation | `internal_exciter=true`, `internal_strum=false`, note-on → `strum` one-block pulse + gate | No input jack; MiniElements exciters MIDI-triggerable via `waveform_exciter`+`strum_gate` |
| Lib integration | mode `cc`, pair `EURORACK-STEREO/rings:rings:cc:rings`, prune firmware/UI/drivers/test/samples/py-generators | Only `dsp/` + `resources.{h,cc}` compile |
| Wrapper | patch adds `RINGS.h` (includes `rings/dsp/part.h`, `rings/dsp/string_synth_part.h`) | Mirrors CLOUDS.h/PLAITS.h |
| Optimisation | library.json `-O3` per lib; no extra -Ds needed | Established law |
| SRAM | hot set: String::ProcessInternal<>, Resonator::Process, FMVoice, Exciter+Tube+Diffuser, Reverb/Chorus/Ensemble, StringSynthOscillator, Oscillator, Limiter, Plucker, NoteFilter, Follower, Svf instantiations + `lut_sine` (20.5 KB) + approx-SVF LUTs | Survey §10; tier if RAM > 75% |
| MIDI notes | note = MIDI note (+bend), `tonic=0`; note-on → strum pulse; velocity unused (strum is bool) | part.cc:701 pitch = note+tonic+fm |
