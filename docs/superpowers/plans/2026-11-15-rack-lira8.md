# rack-lira8 — LIRA-8 (Pure Data) hand-port to RP2350 — TDD (2026-11-15)

## Goal

Port [LIRA-8](https://github.com/MikeMorenoAudio/LIRA-8) (MikeMorenoAudio, BSD —
a Pure Data emulation of the SOMA Lyra-8) as a fifth rack module **rack-lira8**:
hand-written C++ DSP in `rack-rp2350/`, rendered at 32 kHz/16-sample blocks
inside the existing 496 µs budget, with its own CC map, module tab (CC 32),
presets, button and diagnostics. TDD throughout: golden-reference audio
rendered from the Pd patch headlessly, host-side C++ unit + golden tests,
then on-device bench + user ear acceptance.

Constraints from the user: hand port (no hvcc/PlugData runtime in the
firmware); **32 kHz first** (engine sample-rate-agnostic so 44.1 kHz is a
constant change later); collect portability data for a future ctag-tbd
(ESP32) port but do not focus on it now; use subagents for exploration and
data gathering.

## Why a hand port (tooling decision)

- hvcc (pd2dsy's compiler core) is **GPL-3.0** — its generated C must never
  ship in this firmware. It IS used as an analysis tool: its pd2hv parser
  produced `rack-rp2350/test/lira8_ref/graph.json` (the whole patch as JSON,
  subpatch names re-joined via canvas-header geometry + object-census
  fingerprints by `gen_graph.py`), and one full hvcc pass documented object
  support (24× `v` value objects unsupported — trivial in a hand port; all
  GUI plumbing in `gui`/`labels`/`gui.link` is out of scope).
- plugdata = full runtime, GPL, wrong tool. pd2dsy = hvcc + Daisy drivers —
  its adapter shape (generated context ↔ hardware boundary) is the pattern
  reference for our engine↔adapter boundary.

## Patch facts (verified 2026-11-15)

- 4× `lira.voice` (voice-pairs 1-2/3-4/5-6/7-8 at root coords 405,511 /
  435,563 / 595,511 / 625,563), each = 2 osc paths → **8 osc paths**: 8×
  `os.triangle~` (phasor + 2× polyBLEP + one-pole rlpf + samphold PWM; scale
  consts 0.59 / 2.65 / −0.145), FM via `prm.mod` (pow4·2), `prm.sharp`
  (pow2), cos~-morph sensor envelopes (`prm.sensor`, fast 100/100 ms vs slow
  200/8000 ms), vibrato osc~ 3 Hz with per-voice random detune
  (`random 1001` chain), hip~ 3 → per-pair delay bus (`s~ $1-del-$2$3`).
- Subpatches in the main patch: `delay` (120 objs — dual `delwrite~`
  5944 samples @44.1k = 134.7 ms, vd~ reads, comp→expander→tanh per bus,
  feedback + cross-feeds), `master_output` (45), `hyper-lfo` (28),
  `triangle-lfo`, `square-lfo`, `keyboard` (8 sensor sends), plus GUI-only
  `gui`/`labels`/`gui.link`.
- `ma.tanh~` = Pade tanh x(27+x²)/(27+9x²) with clip ±3. `compressor~` =
  attack/release-switched one-pole env follower + dB-domain gain law.
  `expander~` = env~ 512 RMS in dB domain, line~ 11 ms.
- Object census (parse total): ~490 `*~`, ~275 `-~`, ~148 `+~`, min~/max~/
  clip~ heavy, rpole~ 10, phasor~ 10, cos~ 10, line~ 47, vd~ 4, delwrite~ 2,
  samphold~ 8, exp~ 8, wrap~ 8, mtof 18, noise~ 1. No FFT, no tables, no
  files → ~600–800 float ops/sample, well inside 496 µs.
- 32 kHz hazards: `/~ 44100` + `clip 0 22050` in os.triangle~'s rlpf;
  delay length kept as TIME (134.7 ms → 4320 samples @32k ≈ 17 KB f32/buffer).

## Integration surface (rack-rp2350)

Per the architecture exploration (ledger findings below): no base class —
function-pointer registry `RackModuleInfo` (`src/module_registry.h:39-59`) +
per-module adapter headers (template: `src/module_elements.h`), ids in
`src/rack_window.h:31-37`, table `kRackModules[]` (`main.cpp:160-217`), CC 32
switch → `do_module_swap()` (`main.cpp:765-844`, arena placement +
`preset_replay_module` + core-0 I2S reconfig handshake). Per-module
`kSampleRate/kBlockSize/kBudgetUs` (elements 32k/16/496 µs arithmetic to
reuse). A 5th module touches: enum + window symbols + `#error` boot guard +
registry row + adapter include (`#undef LUT_*` hygiene) + `memmap_rack.ld`
overlay member + `ui_link.h` pages + `preset.h` version review +
`mod_engine.h` hook cases + a new `-DRACK_BOOT_MODULE` env. tc code must fit
the A-slot (~58 KB); engine state from the 132 KiB object / 192 KiB buffer
arenas.

## TDD loop

1. **Golden reference** — `pd -nogui` (Pd 0.57.0) renders `patch/` (copy of
   the standalone patch) driven over UDP by a bridge subpatch (sensor/hold/
   seed/param messages + `[writesf~]`); 5 deterministic scenarios (fixed
   seed) → committed 16-bit WAVs.
2. **Unit tests** — host g++ (makefile pattern from
   `EURORACK-STEREO/elements/test/`): osc period/polyBLEP continuity, env
   time constants, tanh vs tanhf, delay interp, compander curves, buffer
   lengths.
3. **Golden tests** — the C++ engine renders the same scenario protocol on
   host; compare vs goldens with tolerance (RMS diff < −50 dB rel,
   correlation > 0.99 — cos/exp implementations differ, bit-exactness is
   not the goal). Red→green per component.
4. **On-device** — `pio run`, flash, 2 s report budget math, nm SRAM
   placement check, user ear test + soak.
