# Elements × Warps (rack-rp2350) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Mutable Instruments **Warps** cross-modulation as a DSP stage inside the rack's Elements module — carrier = resonator main output, modulator = raw exciter (`raw_buffer_`), inserted after metering/panic and before the reverb — with 5 MIDI-CC params (36-40), an Elements-P2 UI page, and zero cost when bypassed.

**Architecture:** The warps DSP sources are vendored under `lib/elements/warps/` (riding the elements library, compiled by the sync script from a pristine top-level `WARPS/` copy + one rack patch). The stage lives in `elements/dsp/part.inc` behind `#if defined(RACK_RP2350_TC)`; the `warps::Modulator` object is placement-new'd from the module pool buffer carve and passed into `Part::Init`. Warps hot code is marked into the existing `.tc_elements.*` SRAM window sections (no linker-script change). The C3 UI needs **no firmware change** — pages are RP2350-defined TELEM tables, so Elements P2 simply gains 5 cells.

**Tech Stack:** PlatformIO + earlephilhower RP2350 core (Arduino C++), vendored Mutable Instruments elements/stmlib, warps eurorack DSP (from the ctag-tbd fork checkout), ESP32-C3 UI over the framed UART link (generic renderer).

**Adapted from:** the ctag-tbd plan (`elements-warps-sdd.md`, 2026-11-16) with these deltas established during grounding:

| ctag plan | rack adaptation | why |
|---|---|---|
| vocoder included, CPU-gated | **vocoder stripped** (6 xmod algorithms) | `warps::Modulator` is ~68 KB with the vocoder (two `FilterBank`s × `delay_buffer_[6144]`); rack RAM is statically partitioned with ~0 slack and no PSRAM. Stripped Modulator ≈ 2 KB. |
| carrier = `0.5*(main+aux)` | **carrier = `main` only** | at the rack's default `space=0`, Elements' aux output IS the raw exciter (`raw_gain=1`), so the ctag carrier would contain exciter bleed. `main` matches the canonical hardware patch (MAIN→CARRIER, AUX→MOD). |
| `modulation_algorithm = val/4095*5` | **`alg = val/127`, clamped ≤ 0.625** | upstream `modulation_algorithm` is 0..1 (`min(alg*8, 5.999)` internally; vocoder from 0.675). The ctag mapping would land every position > 0.125 in the vocoder zone. |
| mod/car levels = pre-gain + `channel_drive` | **levels map straight to `channel_drive[0/1]` (0..1)** | `SaturatingAmplifier` implements the module's LEVEL knobs including the "warm overdrive" top end; the ctag double-applied gain. |
| vocoder at Part block size | n/a (stripped) | `SampleRateConverter<SRC_DOWN>::Process` **silently drops** blocks whose size isn't a multiple of the ratio (3 mid / 4 low) — the ctag block-32 vocoder path was silently broken. Our block 16 fails too; irrelevant once stripped. |
| Warps stage in their fork | stage as `tools/patches/elements/*.patch` | this repo's law: `lib/` is regenerated by `tools/sync_pio_libs.sh`; deltas live as patches, applied `--fuzz=0` to BOTH the rack and the legacy standalone — hence every lib change is guarded `#if defined(RACK_RP2350_TC)` so the standalone stays byte-identical. |
| heap_caps_malloc + PSRAM fallback | **pool carve** (buffer arena, behind the reverb buffer) | RP2350: no PSRAM, heap gate ~30 KiB is spoken for. The reverb engine shrink (Task 2) frees the room inside the existing pool. |

## Global Constraints

- `rack-rp2350/lib/` is GENERATED by `tools/sync_pio_libs.sh` — deltas only as patch files in `tools/patches/{elements,warps}/`, applied strict `--fuzz=0`; a failing patch aborts the sync.
- The legacy `elements-rp2350` build must stay compiling and byte-identical: every lib change guarded `#if defined(RACK_RP2350_TC)` (defined project-wide in `rack-rp2350/platformio.ini`).
- Pool law (`rack_arena.h`): 331,776 B unified pool, `rack_mem_reset()` once per transition, `rack_mem_alloc()` halts loudly on overflow. Worst resident set: rings+clouds = 331,516 B (260 B slack) — **warps state must ride elements' own demand, never new static .bss** (RAM has ~3.7 KB slack total).
- Hot per-sample DSP must run from SRAM: mark with `WARPS_RAM_CODE(token)` → `.tc_elements.warps_<token>`; each token unique. Linker asserts enforce `tc_elements ≤ RACK_CLOUDS_B_OFFSET (0xE400)` and the window bounds.
- Elements renders 16-sample blocks at 32 kHz; per-block budget 496 µs (current worst ~267 µs ominous dwell). Bench gate: max Process ≤ 460 µs with warps active, `i2s stalls: 0`.
- Memory rule (user): **never edit files with Python** — Edit/Write tools only. **Verify "Project build complete" before flashing** — no compound build+flash. **Follow the working reference** — the ctag checkout at `\\wsl.localhost\Ubuntu\home\ubuntu\ctag-tbd\components\mutable\eurorack\warps\` is the verbatim source of truth for the vendored DSP.
- Commits: `[Add]/[Fix]/[Update]/[Docs] <scope>` on branch `rack-rp2350`; ledger (`.superpowers/sdd/progress.md`) updated when tasks land. Never claim hardware-verified without the user's ears/eyes.

**Interfaces (shared vocabulary):**

- Patch fields (added in Task 3): `patch_.warps_algorithm` (0..1, 0 = stage bypass), `patch_.warps_timbre`, `patch_.warps_mod_level`, `patch_.warps_car_level`, `patch_.warps_mix` (all 0..1).
- `Part::Init(uint16_t* reverb_buffer, warps::Modulator* warps_modulator)` (rack build only).
- CC map: 36 warps-algo, 37 warps-timbre, 38 warps-mod, 39 warps-car, 40 warps-mix — all continuous mod destinations.
- UI labels (≤ 10 chars, P2 cells): `W ALGO`, `W TIMBRE`, `W MOD`, `W CAR`, `W MIX`.

- [ ] **Step 7: Create `rack-rp2350/lib/elements/warps/dsp/ram_code.h`** (new file, full content):

```cpp
// Copyright 2014 Emilie Gillet.
//
// Rack RP2350 addition (NOT upstream warps): marker for warps' per-sample DSP
// hot paths, mirroring elements/dsp/ram_code.h. Under RACK_RP2350_TC the
// sections are renamed .tc_elements.warps_<token> so warps' hot code is
// collected into the tc_elements output section (the rack SRAM hot-code
// window's A slot — warps rides the elements module; no new overlay member).
// Everywhere else (standalone builds, host tools) it is a no-op.
//
// Usage: WARPS_RAM_CODE(unique_token) void Foo::Process(...) { ... }
// Tokens must be unique per function (inline/COMDAT and plain copies of one
// shared section name collide at link time).
#ifndef WARPS_DSP_RAM_CODE_H_
#define WARPS_DSP_RAM_CODE_H_

#if defined(ARDUINO_ARCH_RP2040) && defined(RACK_RP2350_TC)
#define WARPS_RAM_CODE_PREFIX ".tc_elements.warps_"
#define WARPS_RAM_CODE(token) \
  __attribute__((section(WARPS_RAM_CODE_PREFIX #token)))
#else
#define WARPS_RAM_CODE(token)
#endif

#endif  // WARPS_DSP_RAM_CODE_H_
```
