# Pico SDK Phase 2 — Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax. Implement task-by-task; each task ends with a commit + push on `rack-rp2350`.

**Goal:** Convert the now-working Pico SDK firmware into a measurable rig: (1) the DSPi-style loopback capture so device-vs-golden works for every module, (2) the placement checker as a build gate, (3) a scripted device suite replacing eyeball benching, then close out the migration items.

**Baseline (all user-confirmed, 2026-11-23):** all 7 modules working by ear on the Pico SDK build; page updates ~500 ms; audio clean. Milestone ledger: `.superpowers/sdd/2026-11-23-pico-migration/progress.md` (the bring-up root causes + commits e212470→c8d6f32).

**Tech Stack:** Pico SDK 2.3.0 (the PlatformIO-bundled SDK at `~/.platformio/packages/framework-arduinopico/pico-sdk`), CMake/Ninja, TinyUSB 0.18 (CDC + MIDI built-in drivers + a UAC1 app driver), arm-none-eabi binutils (stdlib-only Python for the tools), the C3 on esp-idf v6.1.1.

**Global Constraints:**

- The DSP engines stay in `rack-rp2350/` — the single source of truth; nothing copied into `rack-pico/`.
- Every device behavior change is verified on hardware before acceptance (the AGENTS.md law); the user's ears are the audio gate.
- The 320 MHz sys clock is a hard requirement (the chain combinations wedge at 307.2).
- Commits follow `[Add]/[Fix]/[Update]/[Remove] <scope>` on branch `rack-rp2350`, pushed promptly.
- The UAC1 capture follows the DSPi architecture (github.com/WeebLabs/DSPi, GPL-3.0) — pattern-referenced, not copied; keep the attribution comments.
- The full snapshots (~135 B wire) now deliver (dc9eb8a); any new large frame must respect the staging-ring drain law: the pump services the staging ring unconditionally every pass.

## Task 1 — The loopback capture rig (device-vs-golden for every module)

**What:** A second, self-contained UAC1 audio function streams the rack's post-Clip16 stereo output back to the host over USB Audio — the DSPi `DSPI_LOOPBACK` pattern. The tap sits in `RackI2sOut::write16`, so the capture is module-agnostic: whatever the active module renders to the DAC is exactly what the host records.

- [ ] **1a Descriptor extension** (`rack-pico/usb_descriptors.h/.cpp`): interfaces 4 (capture AudioControl) + 5 (capture AudioStreaming) under a second IAD; iso async IN **EP 0x84** (0x83 is MIDI IN now); 2-ch 24-bit packed, discrete 44.1/48 kHz; `wMaxPacketSize` = 52 frames × 6 B = 312 (DSPi's LOOPBACK_EP_IN_SIZE numbers — the ALSA-verified values; the earlier arecord set-params failure used a 16-bit/208 B variant). `ITF_NUM_TOTAL` 4→6. The capture entity ids distinct (input terminal 3, output terminal 4).
- [ ] **1b Capture driver activation** (`rack-pico/usb_capture.cpp/.h`): the parked UAC1 class driver + SPSC ring + fill servo (nominal frames/frame + clamped P-correction, prime-before-stream, overflow/underrun counters) already exist — un-park (add to CMake), retarget the EP to 0x84, and register it alongside… the built-in drivers claim CDC+MIDI automatically; the capture driver is the single `usbd_app_driver_get_cb` return.
- [ ] **1c The tap** (`rack-pico/rack_i2s.cpp`): in `RackI2sOut::write16`, after the bank write, push the L/R int16 pair into the capture ring — post-Clip16, post-gain, post-mute-ramp: exactly the DAC stream. Guarded by `#ifdef RACK_PICO_USB_CAPTURE` (default ON in this build; the option exists to build without).
- [ ] **1d Rate reporting**: `rack_engine_rate_hz` follows the active module's registry sample rate (48k benjolin/plaits/dronecaster, 44.1k lira8, 32k elements/rings/clouds + chain) — set it in `do_module_swap`/`do_chain_engage`/`do_chain_disengage` next to the I2S reconfig; the capture's GET_CUR reports it and the servo's nominal frames/frame follows. The host must reselect the rate on a module switch (documented DSPi contract: wrong host rate = wrong pitch by design).
- [ ] **1e The host capture tool** (`tools/rig_capture.py`): arespawn-free Python capture via `arecord -D hw:Rack\ RP2350 -f S24_3LE -r <rate> -c 2` (or the Python alsaaudio equivalent), converting 24-bit packed → int16/float, writing WAV + the capture-glitch counters read back through the console. Include the PipeWire note: if PipeWire claims the device, `pactl` or `pw-record` with the ALSA node.
- [ ] **1f Bench verification**: flash → the C3 page stays stable → `rig_capture.py` records 10 s of benjolin at amp 100 → the WAV is non-silent (RMS > 0.01) and glitch-counter-clean → repeat one module swap mid-capture (the counters tick but the stream survives). Then the device-vs-golden compare: the benjolin CC snapshot (the user's reference settings in `tools/bjdump_capture.py` `CCS`) → the capture vs the `test/benjolin_ref` golden render → max_abs/corr gates.

**Gate:** a 10-s capture of every module class (benjolin, plaits, elements, lira8) parses as valid WAV at the right rate with zero glitch-counter deltas while idle.

## Task 2 — check_ram_placement.py as a build gate

**What:** `scripts/check_ram_placement.py` (done, cc7a63d) runs against the linked ELF; wire it into the build so a placement regression fails the build, not the bench.

- [ ] **2a** `rack-pico/CMakeLists.txt`: a post-link custom command running `python3 scripts/check_ram_placement.py ${CMAKE_CURRENT_BINARY_DIR}/rack.elf` with `|| true` suppressed — the build FAILS on a non-zero exit. Keep it skippable: `-DRACK_SKIP_PLACEMENT_CHECK=ON` for the host-only builds.
- [ ] **2b** Trim the checker's WARN set once at acceptance: the c0/st/hbw report fields and the remaining `static_ok` WARN entries re-audited (inlined vs gone).

**Gate:** `cmake --build build` fails if a hot symbol regresses to flash; a deliberate regression (a temporary `#undef`) trips it.

## Task 3 — The scripted device suite (exit-code benching)

**What:** `tools/bench_suite.py` — a line-console driver that turns the bench from eyeballing the 2 s report into pass/fail scripts. Modeled on DSPi's scripted suite + liveness sentinel, adapted to the rack's console grammar.

- [ ] **3a The transport**: connect by-id (`/dev/serial/by-id/usb-rack_Rack_RP2350_*`), line-buffered reads, a command→response protocol with per-line echo verification (the stale-bytes law: a newline + retry before trusting the first reply after any reflash), timeouts, and a reconnection path for watchdog resets.
- [ ] **3b The liveness sentinel**: watch the 2 s report for staleness (>5 s without a line = liveness fail), parse `up=` continuity (a backwards `up=` = a silent watchdog reset — fail), parse `max Process ... (budget ...)` against the active module's budget, and `i2s stalls` deltas (0 required for a clean pass).
- [ ] **3c Snapshot/restore**: `preset dump` → collect the PRxx rows into a file; `preset load` + the PRxx rows → restore; verify `preset` prints identical CRC/module/CC count before and after. Also CC snapshot: `status` + the module's cc map → replay a canned CC list → verify `in=` moves on audible modules.
- [ ] **3d The suite scripts** (`tools/bench_cases/`): per-module smoke (swap by console, meters alive, budget respected), swap-storm (N round-trip swaps, zero stall deltas, no watchdog resets — the `crash` command verdict per swap), capture-during-swap (with Task 1), and the chain pairs when T6 lands.
- [ ] **3e Exit codes**: 0 = all cases pass; non-zero with the failing case named — CI/bench-ready.

**Gate:** a full smoke suite runs unattended and exits 0; a deliberate break (a stale uf2) fails with the sentinel.

## Ordering & Risk Notes

- Task 1 first (the user's #1): the capture rig converts every later bench step into data. The highest-risk piece is the ALSA/PipeWire negotiation — mirror DSPi's descriptor numbers exactly before debugging anything custom.
- Task 2 is mechanical (the script exists); do it between Task 1 builds as the gate hardens.
- Task 3 depends on nothing and can proceed in parallel on the bench while Task 1 flashes iterate.
- Task 4 waits for the user's ear acceptance of Tasks 1–3 outputs.
- Known risks: the iso EP bandwidth on the full-speed bus (the DSPi budget math covers 44.1/48 kHz 2-ch 24-bit — verified working there); the PCM5102A strap (LJ vs I2S — now verified I2S by ear with the Philips program); the watchdog reset mid-capture (the suite reconnects and fails the case, per 3a).
