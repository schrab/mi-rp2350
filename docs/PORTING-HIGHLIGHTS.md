# PORTING HIGHLIGHTS — MI modules → RP2350 (Elements + Clouds experience)

**Purpose:** distillation of everything that mattered while porting Elements
(`elements-rp2350/`) and Clouds (`clouds-rp2350/`) to the RP2350 nano. Point a
fresh session/agent at this file BEFORE it starts a RINGS or PLAITS port —
every item below was a real bug, a wasted build cycle, or a shipped fix.

**The one-line summary:** copy `clouds-rp2350/` as the template, keep every
LUT and hot function in SRAM from day one, run the module at its native rate
with the native block size, read the ORIGINAL firmware's main loop for the
per-block call contract, and profile per-mode with stage probes before
optimizing anything.

Reference implementations to copy from: `elements-rp2350/` (simplest: one
synth voice, Dsp-statics rate adaptation) and `clouds-rp2350/` (effect with
memory workspace, CMSIS FFT, time-budgeted search). This file: elements +
clouds debugging war stories. Module RAM estimates:
`.superpowers/sdd/progress.md` (MI modules RAM estimates section).

---

## 1. Proven project architecture (copy, don't invent)

```
<module>-rp2350/
├── platformio.ini        # board rpipico2, f_cpu 240000000L, -O3, -DUSE_TINYUSB, lib_ldf_mode = chain+
├── .gitignore            # .pio/
├── README.md             # CC map + build/flash + report format + known issues
├── src/
│   ├── main.cpp          # core 0: USB MIDI device + PIO-USB host + LED + report · core 1: render
│   ├── midi.h            # NoteStack + 4-byte packet parser + CC map + pending_* slots
│   ├── status_led.h      # WS2812 GP22 (copied verbatim; LED LUT via led_brightness_lut.h)
│   ├── led_brightness_lut.h
│   ├── usb_host_watchdog.c
│   └── ws2812.pio(.h)
└── lib/
    ├── <module>/         # GENERATED by tools/sync_pio_libs.sh — never hand-edit
    ├── stmlib/           # GENERATED
    └── pio_usb/          # VENDORED (copy from elements-rp2350/lib/pio_usb)
```

- **core1_separate_stack = true** (before any include in main.cpp): core 0
  overran the shared 4 KB half at USB attach and corrupted core 1.
- **Core 0 = control, core 1 = audio.** The PIO-USB SOF alarm pool MUST be
  created on core 1 (`alarm_pool_create_with_unused_hardware_alarm(1)` in
  `setup1()`, core 0 waits on a `volatile bool` handshake, then passes the
  pool via `pio_cfg.alarm_pool`). On core 0 the SOF ISR collided with the
  I2S DMA + TinyUSB IRQs and USB enumeration silently failed.
- **PIO-USB host init BEFORE i2s.begin()** — PIO-USB hard-claims all of PIO0;
  I2S then lands on PIO2 (status LED has PIO2 SM0).
- I2S wiring (PCM5102A): BCK GP6, DIN GP8, LRCK GP7 follows, XSMT 3V3.
  USB-A host: D+ GP14, D- GP15. LED: GP22.

## 2. Build system — the rules that cost days

- `tools/sync_pio_libs.sh` regenerates `lib/` from the upstream submodules:
  `sync_project <proj> "SRC:dst[:mode]"`. **mode `inc`** (ELEMENTS, STMLIB):
  the port ships `.inc` duplicates of every `.cc`; delete the `.cc` files.
  **mode `cc`** (CLOUDS, RINGS, PLAITS): the wrapper `<module>_all.cpp`
  #includes the `.cc` files directly — KEEP the `.cc` files and DELETE the
  wrapper (PlatformIO compiles lib sources itself; keeping both = duplicate
  every symbol). **Check which pattern the module uses before choosing.**
- **STM32-only files must be excluded via `srcFilter`** in the generated
  `library.json`: e.g. clouds' `settings.cc` (flash preset persistence,
  `page_storage.h` → `FLASH_ErasePage` etc. — does not exist on RP2350).
  RINGS has the same `rings/settings.cc` — exclude it the same way.
- **The earlephilhower core appends `-Os` AFTER project flags** — project
  `-O3` is silently defeated. Every DSP library needs its own
  `library.json` with `flags: ["-O3"]` (the sync script writes it; never
  rely on project-level flags).
- `lib_ldf_mode = chain+` or the core's TinyUSB symbols go missing
  (`Adafruit_USBD_CDC::begin` undefined). PIO-USB is VENDORED, never
  `lib_deps` (its properties would pull a duplicate TinyUSB).
- **Port deltas live ONLY in `tools/patches/<lib>/*.patch`**, applied by the
  sync script with `--fuzz=0` (conflicts abort loudly). Hand-edits to `lib/`
  are silently reverted on the next sync — this actually bit us once
  (Elements' exciter meter had to be rescued into a patch).
- Patch hygiene learned the hard way: **generate each patch from the state
  the previous patches produce** (apply order is alphabetical). A patch
  generated against the final state will include earlier patches' hunks and
  get rejected mid-chain. Keep file sets disjoint between patch files.
  Also: `< "$p" </dev/null` — the second redirect wins, patch reads EMPTY
  input, "succeeds" with exit 0 and applies nothing. One redirect only, and
  verify the result.
- **Patch-diff recipe (exact mechanics)**: snapshot the fresh lib tree TWICE
  with the module leaf dir preserved on both sides, e.g.
  `cp -a lib/rings/rings /tmp/rings_a/rings && cp -a lib/rings/rings /tmp/rings_b/rings`
  (missing the leaf dir on one side makes diff emit the WHOLE tree as
  additions — hit twice in the rings session), edit `/tmp/rings_b` with
  Read/Edit/Write only, then
  `cd /tmp && diff -ruN rings_a/rings rings_b/rings | sed -e 's|rings_a/rings|a/rings|g' -e 's|rings_b/rings|b/rings|g' > tools/patches/<lib>/NN-name.patch`,
  **Read the generated patch and confirm it contains only the intended
  hunks** (a full-tree `@@ -0,0 +1,N @@` loop = snapshot layout wrong), advance
  fresh with `cp -a /tmp/rings_b/. /tmp/rings_a/` between patches, and
  round-trip: re-run the sync script + `diff -ruN /tmp/rings_b/rings
  lib/<proj>/lib/<lib>/<lib>/rings` empty + other projects' libs untouched.

## 3. THE audio-budget law: nothing hot in flash

XIP flash execution is THE module killer on RP2350 — cache misses cost more
than the entire per-block budget. Elements went 1.1 ms → 240 µs mostly from
SRAM placement; Clouds' spectral ShyFFT was 14.4 ms *because of flash* before
we understood the real compute split.

- **Every per-sample function and EVERY LUT goes to SRAM** via
  `.time_critical.*` sections (the linker script maps them into `.data`,
  crt0 copies them at boot). Per-lib macro header, e.g.
  `lib/<module>/.../ram_code.h` (see elements/clouds):
  `#define RAM_CODE(token) __attribute__((section(".time_critical." #token)))`
  guarded by `#if defined(ARDUINO_ARCH_RP2040)`.
- **Unique token per function.** An inline/COMDAT copy and a plain copy
  sharing one section name = link-time "section type conflict". Two
  same-flags weak copies (template instantiations) MAY share a token.
- **`#pragma GCC section text="..."` is a NO-OP** under PlatformIO's
  `-ffunction-sections` — per-function attributes are the only thing that
  works. (Cost us a build cycle on the CMSIS FFT.)
- **Initialized globals in a header = definition in every including TU** →
  multiple-definition link errors. Declarations in the header, definitions
  in one `.cc`.
- **Verify with nm after every build:** hot symbols must sit at
  `0x2000xxxx`, not `0x1000xxxx`
  (`arm-none-eabi-nm -C <elf> | grep ...`). Template instantiations may be
  inlined into an SRAM caller (fine) — check the caller.
- **Tables: mark selectively.** The linker keeps tables for every size a
  switch references (CMSIS init references all FFT lengths → ~100 KB of
  unused tables still in flash). Only the actually-used size's tables go to
  SRAM (we moved twiddleCoef_4096 etc. = 56 KB; the rest stay in flash).

## 4. Read the original firmware's main loop — the call contract

The biggest non-obvious bug of the whole Clouds port: `Prepare()` must be
called EVERY block (it applies mode changes and updates
`previous_playback_mode_`); calling it once in setup() made `Process()`
latch into its silent early-return after the first mode change (`max
Process` collapsed to 4 µs, no audio, no error). **Before writing your
render loop, open the original module's `*.cc` firmware entry (clouds.cc,
rings.cc...) and copy its per-block call sequence exactly** — e.g. clouds:
`processor.Prepare(); processor.Process(in, out, kBlockSize);`.

- Apply MIDI-driven parameter changes BETWEEN blocks via `pending_*`
  slots (core 0 writes, core 1 consumes at the top of the render loop).
  Never mutate module state mid-`Process()`.
- **Block size = the module's native `kMaxBlockSize`**, sample rate = the
  module's native rate. Don't resample — set the I2S clock to match:
  - Elements: 32 kHz / 16-sample blocks (budget 496→1000 µs pattern)
  - Clouds: 32 kHz / 32-sample blocks (budget 1000 µs)
  - RINGS: 32-sample blocks, `Dsp::setSr()` exists already (vb added it —
    same pattern as Elements' `Dsp` statics; the statics are declared in
    the lib but DEFINED in main.cpp — check and define them)
  - PLAITS: `kSampleRate = 48000` is a `static const` in dsp.h — either
    run I2S at 48 kHz (simplest) or patch a setter in. Block = 24.
- Budget arithmetic in the report: `1000000UL * kBlockSize / kSampleRate`
  — the other grouping silently truncates (printed 992 instead of 1000).

## 5. I2S DMA bank sizing — bursts vs sustained

Two different overrun shapes, two different cures:

- **Sustained** over budget (stretch mode was 1156 µs every block): the bank
  cannot help — the mode must actually get faster. Profile, find the pig,
  fix or time-budget it.
- **Burst** (spectral: 13.5 ms transform burst every 32 blocks, amortized
  ~560 µs/block): sustainable IF the DMA bank absorbs the spike.
  `i2s.setBuffers(N, 16)` — bank depth = N ms (N=32 → 16 ms). Rule:
  bank_ms > spike_ms with margin, and average < budget. Bank RAM is cheap
  (N×16 frames × 4 B).

The classic bank bug: `i2s stalls` counts only SLOW writes — it stays 0
while the bank silently drains during bursts. It cannot detect underrun
caused by a spike. Do the spike-vs-bank math from the profile.

## 6. Profiling pattern (before and during optimizing)

1. Instrument per-stage with `time_us_32()` probes around the suspect
   regions (`extern "C" volatile uint32_t dbg_*` maxima, printed in the 2 s
   report, reset per report). See stft.cc/wsola_sample_player.h history.
2. `time_us_32()` is a **static inline in pico-sdk 2.x** — `#include
   "pico/time.h"`, do NOT declare it extern (undefined-reference at link).
3. Measure per MODE with isolated sequences; a 2 s max-window mixes modes.
4. Strip the probes after acceptance (they live in generated lib files —
   regenerate the patch afterward!).
5. Optimization wins so far, in impact order: SRAM placement (7×), CMSIS
   real-FFT instead of ShyFFT (10× on spectral), time-budgeted search drain
   (stretch 2.6 ms → 0.34 ms). Sound-neutral pacing (spreading work over
   blocks when the average fits) beats algorithm changes that alter tone.

## 7. MIDI, exciter, panel

- `midi.h` pattern (copy from clouds-rp2350): NoteStack (last-note
  priority), 4-byte USB-MIDI packet parser (pkt[0] = cable<<4|CIN, status
  in pkt[1], data at pkt[2..3]), CC map, `pending_*` slots. Note-ons also
  pulse the module's TRIGGER where applicable.
- **Test exciter**: the hardware has NO audio input; standalone builds need
  a MIDI-triggered input source (clouds uses a pitched pluck / gated tone;
  CC 11 = 0 is the reserved "chaining input" slot for multi-module builds).
  Make it MUSICAL (pitched pluck, not noise) so ear checks are meaningful.
- **Panels**: copy `tools/elements_panel.html` / `tools/clouds_panel.html`
  (single-file Web MIDI; knobs via the `--deg` notch rotation; headless
  byte validation with a stubbed `navigator.requestMIDIAccess` +
  `--headless=new --dump-dom`; retry the dump — virtual-time has races).
  LED lesson: inactive LEDs must be DARK, active bright+glow.
- **Host MIDI delivery is flaky through the ALSA seq layer** (dense
  sequences lose events). For self-testing use the raw device:
  `python` writing bytes to `/dev/snd/midiC2D0` (or `amidi -p hw:X,0,0`).
  Put a `note_on_count` + max-since-report in/out RMS in the report so
  "silent" complaints are diagnosable in one serial line.

## 8. Flash + monitoring procedure

```sh
pio run -d <module>-rp2350
# button-BOOTSEL is the RELIABLE path (the 1200-bps touch wedges ~50%:
# some touches reboot straight to firmware; BOOTSEL auto-ejects in ~10 s
# if nothing writes). Hold BOOTSEL, replug, then:
udisksctl mount -b /dev/sdb1     # retry in a loop ~3 s: udisks probes late
cp <...>/firmware.uf2 /run/media/$USER/RP2350/ && sync
# board reboots; CDC returns WITHOUT replug (500 ms detach/attach fix)
stty -F /dev/ttyACM0 115200 raw -echo; cat /dev/ttyACM0
```

`pio run -t upload` needs a udev rule (Error 249 otherwise). "No sound"
during a flash window = the board sitting in BOOTSEL; retry the touch
before suspecting anything.

## 9. RINGS port prep (checked against RINGS/src)

- Wrapper: `rings_all.cpp` includes `.cc` files directly → **mode `cc`**.
- `rings/settings.cc` = STM32 flash persistence → **exclude via srcFilter**
  (same as clouds' settings.cc).
- Rate: `rings/dsp/dsp.h` already has the vb `Dsp::setSr()` class (like
  Elements) — define its statics in main.cpp (`sr`, `a3`), call
  `Dsp::setSr(<rate>)`. Native blocks: `kMaxBlockSize = 32`.
- Render: `Part::Process(performance_state, patch, in, out, aux, size)` —
  `PerformanceState` (strum/polyphony/normalize on) + `Patch` map to CCs;
  note-ons → strum.
- RAM: polyphony 4 × (2048+1024 floats string delay+stiffness) ≈ 49 KB +
  modal resonator (64 SVF modes) + plucker ≈ **55-60 KB total** — easy fit.
  Resources.cc is modest (1567 lines) but still SRAM the LUTs.
- Strum/polyphony behavior: each note-on re-excites; map the panel keyboard
  directly (no exciter needed — Rings is a synth like Elements, its input
  IS the excitation).

## 10. PLAITS port prep (checked against PLAITS/src)

- Wrapper: `plaits_all.cpp` includes `.cc` files directly → **mode `cc`**.
  16 engine .cc files + speech synthesis (.cc) all compile.
- **Rate: `kSampleRate = 48000` is hard-wired `static const`** in
  plaits/dsp/dsp.h (no setter). Decision: run I2S at 48 kHz (recommended —
  zero code risk) or patch a setter. Block = **24 samples** (budget 500 µs
  at 48 kHz).
- `plaits::Voice::Init(stmlib::BufferAllocator* allocator)` — needs a
  static buffer pool carved by the allocator (see clouds' BufferAllocator
  use). All 16 engines are members of Voice → their combined RAM is always
  allocated; measure with nm after the first build. Resources.cc is BIG
  (10.5k lines — wavetable/speech LUTs): SRAM the ones the selected engine
  touches, measure first.
- `Voice::Render(patch, modulations, Frame* out, size)` — Frame = {l, r}
  floats(?) at 48 kHz; check `Frame` in voice.h. Engine selection via
  `patch.engine` (0-15) — panel: engine selector buttons (like clouds'
  mode buttons).
- Speech engines need `lpc_speech_synth_*` tables — flash-resident
  probably fine (low duty), but profile if used.
- RAM estimate ~15-25 KB state + engine buffers (allocator) — measure.

## 11. Acceptance checklist (every port)

1. `pio run` SUCCESS; round-trip `tools/sync_pio_libs.sh` reproduces the
   tree (git status clean).
2. nm: every hot function + LUT at 0x2000xxxx.
3. Flash (button-BOOTSEL), boot log (`I2S up`, LED self-test), 2 s report
   with correct budget math.
4. Agent-played raw-MIDI sequence per mode: notes delivered (counter),
   in/out meters live, zero stalls.
5. Stage profile per mode; every burst either < block budget or < DMA bank.
6. User ear check; 30 min soak; ledger + README (CC map + report format).
